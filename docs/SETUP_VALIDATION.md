## Исторические ограничения до перезагрузки

- Установленная сборка alpha; проверен конкретный набор команд, а не все возможности версии.
- Legacy Windows sandbox возвращает `helper_unknown_error: setup refresh had errors` из-за занятого runtime-файла. Для штатной работы устранить блокировку либо выбрать проверенный MXC и повторить чтение/проверку политики именно custom reviewer; обходом reviewer проблему не компенсировать.
- Смена доверия не обновляет гарантированно уже начатый сеанс. Новый основной сеанс из папки проекта загрузит актуальные конфиги; текущий чат использует описанный fallback, если selector custom type отсутствует.
- Живые sandbox overrides родителя могут переопределить роль; фактический режим проверять при каждом способе запуска. Ограничения каталогов backend/android/web в инструкциях — процесс, не ACL.
- Лимит текущего чата — четыре активных агента включая координатора; проект ограничивает три дочерних потока. Пять ролей используются по необходимости, не все сразу.
- Нет Git/исходного коммита, поэтому параллельная запись пока последовательная; коммит по-прежнему требует отдельного разрешения.

Первоначально следующим техническим шагом было восстановление Windows sandbox и повтор canary/чтения reviewer; после перезагрузки этот проверенный цикл завершён успешно. Следующий продуктовый шаг — утверждение предложений из DECISIONS.md и отдельное поручение на первую реализацию. Архитектура этим отчётом не утверждается. Отсутствие Git/worktree и необходимость проверять фактическую политику каждого способа запуска остаются актуальными.
