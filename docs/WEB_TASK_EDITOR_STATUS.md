Статус: реализовано и проверено 20.10.2026. Основание — прямое поручение владельца, записанное в [DECISIONS.md](DECISIONS.md). Основная форма: название, дата, единое текстовое поле интервала (`10:00 - 11:30`) и полный объём. Остальные параметры сгруппированы в расширенных настройках. Backend/API и предметные правила U1 не меняются.

## Задержка печати

Read-only explorer установил цепочку: `DraftSession.change` немедленно обновляет snapshot, затем уведомляет runtime; `WorkspaceContent` подписан на local state и снова рендерит календарь. Недельный календарь заново вычислял14 границ, каждая вызывала1681 `Intl.formatToParts` без кэша результата. После аварийного сохранения и IDB reload уведомления повторялись. Это синхронная работа главного потока, а не намеренный debounce или ожидание ответа API.

Координатор отдельно реализовал ограниченный LRU-кэш128 результатов `localCandidates`, сохранив прежний полный перебор offsets, DST-поведение и проверки. Внутренние массивы/элементы неизменяемы, наружу выдаются копии; ключ содержит точные localStart/timezone. Ошибки не кэшируются. Частота аварийных записей, CAS и runtime не менялись. Во время этой фазы frontend подтвердил STOP всей Web-записи, затем получил обратно единоличное владение web/** для UI.

Фактический Node CPU probe координатора (медиана5 повторов одного workload):14 границ недели119.764мс →0.021мс после прогрева;7 одинаковых localCandidates59.049мс →0.004мс. Новые meaningful tests проверили отсутствие повторного сканирования, защиту от изменения возвращённого массива/элементов, раздельные timezone keys и вытеснение старых записей. Targeted time suite12/12 и TypeScript — PASS.

Живой браузер с открытым недельным календарём до изменения: автоматизированный ввод «Проверка ввода» прервался Input.insertText deadline примерно через6.8с, отображались только6 символов. После оптимизации тот же вызов завершился за1136мс с полной строкой. Это полное время действия автоматизации с накладными расходами, не покадровая задержка клавиши. В обоих случаях тестовый ввод закрыт без сохранения; пять прежних ручных черновиков не менялись.

## Новая форма

Frontend реализовал UI на одном parent draft/session: исходная строка времени сохраняется без принудительного форматирования при печати; старые локальные черновики адаптируются только в редактируемой копии, frozen pending не переписываются. Пустота, начало без конца (`10:00`) и конец без начала (`- 11:30`) сохраняют U1-семантику. Дефис, en dash и em dash распознаются при проверке; строка не переписывается при каждом символе. Незаконченный конец (`10:00 - 1`) и trailing dash блокируют Create, но сохраняются в черновике. Ночь требует явного day-offset; timezone/DST не сбрасываются при обычном редактировании текста.

Расширенная форма содержит четыре отдельных экрана: «Описание и характеристики», «Повторение», «Часовой пояс и фиксация», «Когда можно выполнять». Переходы не создают серверную задачу или копию ручного черновика; Enter вне основной формы не отправляет Create. Перед сменой экрана проверяется native badInput числовых полей. После ACK настройки доступны только для просмотра. Runtime/CAS/IndexedDB schema и зависимости не менялись.
