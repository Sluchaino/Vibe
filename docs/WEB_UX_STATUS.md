# Календарь и создание задачи — WEB-UX-01

Статус: реализовано локально и проверено, 16.10.2026. Источник: четыре правки владельца, обсуждение пояснений о часовом поясе/допустимых интервалах и последующее поручение «исправь правки». [Решение](DECISIONS.md).

Последующее уточнение владельца WEB-UX-02 переносит выбор начала в исходную форму и меняет работу с черновиками; его актуальный результат фиксируется отдельно в [WEB_DRAFTS_STATUS.md](WEB_DRAFTS_STATUS.md). Ниже сохранён фактический отчёт предыдущей проверки, а не обещание прежнего поведения после уточнения.

Координатор отвечает за требования, документацию, проверку браузера и сборку результата. Architect анализирует существующий API и восстановление многошагового сценария без записи. Frontend — единственный автор web/**; Backend, контракт и схема БД не меняются. После остановки записи reviewer проверяет результат в отдельном технически read-only/approval never сеансе. Коммиты и отправка изменений не разрешены.

Критерии:

1. Начать создание задачи можно из календаря, не переходя во вкладку задач.
2. В начале создания выбирается дата; последующие явные шаги создают отдельное выполнение и по желанию размещают его на выбранную дату/время. Выполнение только с датой видно в соответствующем дне как «Без времени», не создаёт календарного блока и не занимает время. Частичный успех не объявляется полным размещением; после reload есть продолжение без повторного создания уже существующих сущностей. S1 pending не заменяется новой командой.
3. В обычных подписях времени нет GMT+3. Часовой пояс сохраняет прежний смысл; для однозначного времени смещение выбирается автоматически, для неоднозначного требуется выбор, несуществующее время отклоняется.
4. Допустимые интервалы — необязательная настройка с примером и понятным названием. Сворачивание не удаляет существующие ограничения.

## Реализация и фактические проверки

Frontend изменил формы, календарь и связывающий App, добавил TaskCreationFlow и небольшие helpers creation/availability/placement-draft. S1 runtime получил awaited сохранение обычного DraftRecord с прежними identity guards; схема IndexedDB не менялась. Backend, общий контракт, зависимости и lock-файл не изменены.

Автор выполнил `scripts/dev.ps1 web -WebCommand check`, `test`, `build`: **все PASS, 75/75 тестов, 0 skipped**. Восемь новых проверок покрывают durable continuation/ACK cleanup/reload, ожидание записи и её отказ до HTTP, неизменный pending при потере ACK, date-only selection, единственный offset и DST fold/gap, исключения, формат подписи и начальную дату placement. Прежние 74 Backend-теста относятся к завершённому S1; при этой Web-правке серверный suite повторно не запускался.

Координатор проверил в настоящем браузере с работающим Backend/PostgreSQL:

- Из календаря выбрана дата 20.10.2026; «Новая задача» открылась на этой дате. В форме дата изменена на 21.10.2026, описание сохранено. После reload появилась возможность продолжить с сохранённой датой, без повторного создания описания.
- Создано выполнение на 21.10; «Готово без времени» показало его в выбранном дне, без блока и занятости. [Снимок date-only](images/vibe-calendar-date-only.png).
- «Выбрать время» подставило 21.10 в 09:00, а не сегодняшний день; изменение часов показало preview без ручного выбора offset. В итоге сохранён один блок 21.10.2026, 10:00–11:00, 60 минут; прежняя date-only карточка исчезла. [Итоговый календарь](images/vibe-calendar-create-ready.png).
- Добавленный допустимый интервал 09:00–18:00 сохранился после сворачивания/раскрытия. Пустое исключение, скрытое перед submit, автоматически раскрылось и получило фокус; описание не отправилось до исправления. Проверочные ограничения затем убраны до сохранения задачи.
- Для Europe/Berlin 25.10.2026 02:30 появились два явных выбора; второе вхождение построило preview. 29.03.2026 02:30 отклонено без автоматического сдвига. Эти проверки не отправляли placement; затем возвращены Europe/Moscow и выбранная дата 21.10.
- Обычные подписи блока без GMT. Создана одна демонстрационная задача «Проверка календаря — выбранная дата» с одним выполнением и одним блоком; она оставлена в локальной БД. Исходная задача 13.10 сохранена. Созданный проверкой локальный continuation убран после завершения; исходно локальных черновиков было 0.

Координатор сверил рекомендации с runtime cleanup и существующими DTO и передал frontend.
