# WEB-UX-05 — отдельная форма даты и времени

Статус: реализовано и проверено 20.10.2026. Основание: прямое поручение владельца и [DECISIONS.md](DECISIONS.md), WEB-UX-05. Изменение интерфейса на утверждённом U1 API; Backend, БД, runtime/storage, контракт и зависимости не меняются.

Основная форма содержит название, описание, кнопку «Дата и время» с краткой сводкой, категорию, важность, сложность и приоритет. Отдельный экран содержит дату/часы/часовой пояс, повторения и конец серии, полный объём, фиксацию и допустимые интервалы. Кнопки «Готово» и «Назад к задаче» возвращают к основной форме без отправки на сервер. Сохраняются один draft/session, прежние IDs и ввод; переход сам по себе не создаёт ручной черновик. Фокус переносится к заголовку и обратно к кнопке.

Frontend — единственный автор main web/**, координатор — документация и живая проверка. Worktree заморожена. Реализация касается UnifiedTaskForm, TaskTimeSettings, task-time-summary, узких client validation в task-timing/availability, стилей и существующих тестов. Commit/push не поручены.

Первый полный check автора и координатора: TypeScript PASS, 158/158 Node PASS без пропусков, Vite build PASS (63 модуля). После исправления замечания автор повторил check, полный suite158, build и diff-check — PASS. Поддельный DOM-тест для браузерной validity не добавлялся; сценарий проверен реальным клавиатурным вводом.

Браузер: основная форма сокращена; название/описание/время сохраняются при возврате; краткая сводка обновляется; переходы не увеличивают число ручных черновиков. Пустой N возвращает на экран времени с видимой ошибкой до отправки. Enter в числовом поле времени не создал задачу. Явно сохранён один собственный тестовый черновик: число4→5 вызвано нажатием «Сохранить черновик», последующее открытие использовало прежнюю запись. После возврата создана демонстрационная задача «Проверка отдельной формы времени»:8 ноября09–10, вычисленный объём60 минут и настоящий календарный блок, без повторения; прежние пользовательские задачи не менялись. После ACK временные поля доступны только для просмотра. Закрытие успешной формы не вызвало ложного сохранения черновика.

Отдельный официальный reviewer с фактическими read-only/approval never нашёл один P2: незавершённый native number badInput (`1e`) при переходе терял validity и превращался в пустой объём. Исправлен общий возврат для «Готово», «Назад» и обработанного submit: при badInput экран и поле остаются смонтированы, выводится сообщение и возвращается фокус. Обычная пустота возврат не блокирует. После полной перезагрузки координатор ввёл `1e` клавишами, подтвердил native badInput=true и проверил: «Готово» удерживает экран; Tab→«Назад» также удерживает; явная очистка разрешает возврат и убирает сообщение. Первая попытка без reload использовала устаревшую HMR-версию и не считалась итоговой проверкой.

Адресное повторное статическое ревью подтвердило P2 resolved; конкретных оставшихся замечаний нет. Дополнительно проверены client validation часов окон и дат исключений, заменяющие прежние native проверки размонтированных полей. Reviewer приложение/тесты не запускал и не выдавал авторские PASS за свои. Клавиатурно проверен один локальный браузер; отдельная матрица мобильных браузеров не запускалась. Финальный whitespace/link-check выполнен координатором. Коммитов/push нет.
